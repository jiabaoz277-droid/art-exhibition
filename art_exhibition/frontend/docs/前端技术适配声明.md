# 前端技术适配声明

> 项目：高校艺术赛事投稿助手（前端阶段）
> 配套：`prd-art-exhibition.md`、通用技术栈手册、通用前端技术栈手册（V1.0）、`../阶段文档-step5.md`

## 1. 项目判断
- 产品类型：高校艺术赛事投稿助手（表单投稿 + 后台管理 + AI 核验/简报/问答）。
- 主要用户：①艺术家（链接直投）②管理员（后台）。
- 主要终端：桌面 Web 为主，兼顾移动 Web。
- 新项目或已有项目：**新前端项目**；后端 FastAPI（端口 8000）已就绪并验证。
- 本阶段业务目标：用 Next.js 重做投递页 + 后台页，打通真实后端全链路。

## 2. 输入资料
- PRD：已读取。后端手册：已读取。前端手册：已读取。
- 接口文档：已有（后端 `/api/v1` 已实现，OpenAPI 见 `http://127.0.0.1:8000/docs`）。
- 设计稿：**无** → 按中性方案先做代表页。
- 现有代码：`art_exhibition/`（FastAPI）。

## 3. 技术选择
- 框架与版本：Next.js（App Router）+ React + **TypeScript strict** + Tailwind CSS 4。
- 样式与组件策略：Tailwind + CSS 语义变量；自建轻量 UI 组件（Button/Input/Card 等），不引入完整组件库。
- 数据请求与状态策略：集中式 `lib/api` 客户端 + React 状态；后端为事实来源；不引入 TanStack Query / Zustand（两页无多页共享缓存复杂度）。
- 流式通信策略：无（核验/简报为同步短请求），普通 HTTP。
- 表单方案：自建受控表单（4 步向导），不引入 RHF+Zod（字段少）。
- 测试方案：ESLint + `tsc --noEmit` + Vitest(RTL) + 生产构建；Playwright 本阶段暂缓。
- 部署环境：本地 dev + prod 预览（上线见部署手册③）。

## 4. Agent 状态
- 后端状态映射：`applicants.status`（submitted/checked）→ 前端仅展示核验结果；投稿为同步短请求，映射 `submitting → succeeded / failed`。
- 等待用户确认：无多轮 Agent 确认（投稿 4 步为前端向导）。
- 取消/重试/恢复：提交失败可重试；无长任务断线恢复需求。
- 任务 ID：`applicant_id` 作为投稿结果标识（无持久任务流）。

## 5. 页面与产物
- 核心页面：`/s/[token]`（4 步投稿）、`/admin`（登录+活动管理+总览+明细+导出+简报+问答）。
- 核心闭环：进入投递页 → 4 步投稿 → 看到核验报告；后台建活动 → 看统计 → 筛选/导出 → 简报/问答。
- 产物类型：核验报告(text)、工作简报(text)、CSV(file)、作品图片(image)。
- 响应式目标：390 / 768 / 1280 / 1440。

## 6. 偏离本手册的地方
- **Playwright E2E 暂缓**：两页、同步短请求、无长任务流；本阶段用 Vitest+RTL 覆盖组件/逻辑，浏览器真实验收由产品经理按清单完成，后续再补 E2E。
- **Node 版本**：本机 Node v26.7.0（高于参考基线 Node 22 LTS），Next 16 兼容，沿用本机版本。
- **不引入组件库/状态库/表单库**：两页无对应复杂度（符合手册 C 层"无复杂度不引入"）。

## 7. 待确认事项

- 无其他影响范围/成本/工期的问题。
