# 技术适配声明

> 项目：高校艺术赛事投稿助手
> 配套文档：`prd-art-exhibition.md`（已定稿）、`AI产品Vibe Coding通用技术栈手册(1).md`（V2.1）
> 生成日期：2025-08-28

## 1. 产品形态判断

- **产品类型与核心任务**：高校艺术赛事投稿助手——主办方建活动生投递链接 → 作者分步投稿（简历+联系方式+作品）→ AI 核验材料完整性与格式 → 后台查看/筛选/按分类批量导出 → AI 查数据、生成工作简报。
- **核心交互**：分步表单提交 + 后台管理（AI 产出为一次性核验报告与简报，**非多轮对话**）。
- **开发路径**：**后端先行（路径 A）**。原因：产品以表单提交、后台导出、报告生成为主，交互不是 Agent 能力本身，符合手册"表单提交/后台生成类 → 后端先行"。
- **当前阶段范围**：PRD 的 Step 5 第一阶段 = 跑通「建活动 → 投稿 → AI 核验 → 后台查数/导出 → 简报」全链路，交付 `art_exhibition/` 应用。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.11.x | 手册 B 默认；本机用 `/opt/homebrew/bin/python3.11`（3.11.16），弃用系统 3.9.6 |
| FastAPI | 手册 B 默认；自动 OpenAPI 文档可作 API 验收入口，Pydantic 内置校验（详见第 4 节 Flask 说明） |
| Pydantic | 接口与模型输出结构校验 |
| pytest | 第一层 mock 自动化测试 |
| Git | 初始化仓库 + `.gitignore` |
| OpenAI 兼容接口调用 | 国内模型可配，PRD 明确 |
| Jinja2 模板直出投递页+后台页 | 本产品核心界面即这两页，作为最小验收界面 + 产品实际界面（非临时壳） |

## 3. 触发的按需模块

| 模块 | 由哪条需求触发 | 本阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy | 多实体关系（活动/投稿/作品/核验报告）+ 筛选统计 + `run_sql` 只读查询 | ✅ 引入 |
| 文件上传处理（python-multipart + 白名单校验） | 作品图片 + 简历上传 | ✅ 引入 |
| Jinja2 模板 | 投递页 + 后台页 | ✅ 引入 |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 恢复条件 |
| --- | --- | --- | --- | --- |
| （PRD 草图中写 Flask） | **FastAPI** | PRD Step 4 架构草图写了"Flask"，手册默认 FastAPI；FastAPI 自带 OpenAPI 文档 + Pydantic，与手册统一 | 仅实现层差异，不影响产品目标/成本/安全 | PM 若坚持 Flask 可改回，成本极低 |
| Alembic（数据库迁移） | 带 `schema_version` 的建表初始化脚本 | MVP 仅 4 张结构稳定的表，避免过度工程 | 表结构变更需手写迁移 SQL | 表结构频繁变更或进生产时引入 |
| 正式前端 Next.js | Jinja2 模板直出两页 | PRD 明确只做两页、无注册、规模 100–300 件、单进程 | 无独立前端阶段 | 后续需响应式/富交互时再做正式前端 |
| SSE / 任务队列 | 同步请求 + 超时重试 | 核验/简报为短请求，单进程可可靠完成 | 响应同步阻塞 | 实测 >10s 或并发增加时引入 SSE 或提交+轮询 |
| PostgreSQL（生产） | SQLite | PRD 明确本阶段 SQLite | 并发/数据量上限 | 用户量、并发、合规要求提高时评估迁移 |

## 5. 强制底线检查

- **密钥与隐私**：✅ 通过。`ADMIN_KEY` 与模型 Key 走 `.env`（已加入 `.gitignore`），仅提交 `.env.example`；后台密钥与模型 Key 不回显、不进日志、不进前端。
- **数据与任务可恢复**：✅ 通过。SQLite 持久化；投稿提交先落库再触发核验；状态用受控枚举。
- **输入输出校验**：✅ 通过。Pydantic 校验接口；上传白名单（扩展名+真实内容类型+大小）+ 文件名清洗；`run_sql` 仅允许 SELECT/WITH。
- **错误与日志边界**：✅ 通过。统一错误结构，不泄露堆栈；日志不记密钥与敏感原文。
- **测试与真实模型验收**：计划 = 第一层 pytest mock（业务逻辑、解析器、错误路径）+ 第二层真实模型端到端冒烟（投稿核验、简报两条链路）。**无 Key 时明确声明冒烟待验，不以 mock 冒充。**
